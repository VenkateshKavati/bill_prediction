# ⚡ Next Month Electricity Bill Prediction — Warangal

Predicts a customer's **next month electricity bill (₹)** from their household details, monthly usage, weather and recent bill history, with an interactive **Streamlit** app on top.

Built for the **HCLTech Data Science Hackathon**.

---

## 1. Problem statement

The electricity distributor wants to forecast each customer's next bill so that:
- customers get an early warning before a high bill (e.g. before summer), and
- the utility can plan revenue and spot unusual bills.

**ML task:** supervised regression · **Target:** `next_month_bill`
**Main metric:** MAE in ₹ ("on average the prediction is off by ₹X"), plus RMSE, R² and MAPE.

---

## 2. Dataset

Synthetic data for one location (Warangal, Telangana), generated by `generate_bill_data.py`.

| Item | Value |
|---|---|
| Customers | 200 |
| Months | 23 per customer (Nov 2024 – Sep 2026) |
| Rows | 4,600 |
| Columns | 14 |

| Column | Type | Description |
|---|---|---|
| `customer_id` | ID | Customer code (not used as a feature) |
| `area` | Categorical | Hanamkonda, Kazipet, Warangal Fort, Subedari |
| `connection_type` | Categorical | Domestic / Commercial |
| `house_type` | Categorical | 1BHK, 2BHK, 3BHK, Independent |
| `family_size` | Numeric | Number of people |
| `num_acs` | Numeric | Number of air conditioners |
| `has_solar` | Categorical | Rooftop solar: Yes / No |
| `payment_mode` | Categorical | UPI, Cash, Net Banking, Card (no effect on bill, dropped) |
| `month` | Date (YYYY-MM) | Billing month |
| `avg_temp_c` | Numeric | Average temperature (°C) |
| `humidity_pct` | Numeric | Humidity (%) |
| `units_consumed` | Numeric | Units used (kWh) |
| `bill_amount` | Numeric | This month's bill (₹) |
| **`next_month_bill`** | **Target** | Next month's bill (₹) |

About 5% of values are missing in 7 columns, on purpose, so the preprocessing has something to handle.
Bills follow a slab tariff (Domestic and Commercial rates differ), peak in April–May because of AC use, and drop sharply with solar.

## 4. Setup and running

```bash
# 1. create and activate a virtual environment
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # Mac / Linux

# 2. install packages
pip install -r requirements.txt

# 3. train the model (creates bill_model.joblib, about 1 minute)
python train_model.py
#    or open bill_prediction.ipynb and Run All (choose the venv kernel)

# 4. start the app
streamlit run app.py
```
The app opens at http://localhost:8501.

> Always train and run the app **in the same environment**. A model saved with one scikit-learn version may not load in another.

## 5. ML workflow (notebook steps)

| # | Step | What is done |
|---|---|---|
| 1 | Business understanding | Goal, ML task, success metric, naive baseline |
| 2 | Data collection | Load the CSV |
| 3 | Data validation | Types, missing values, duplicates, range checks, continuous monthly history |
| 4 | Initial EDA | Target distribution, seasonality, bill by connection/solar, correlation matrix |
| 5 | Target & feature identification | Target, features to drop, history (lag) features |
| 6 | Train/val/test split | **Time-based**: Train Nov 24–Mar 26 · Val Apr–Jun 26 · Test Jul–Sep 26 |
| 7 | Missing value imputation | Median (numeric), most frequent (categorical) |
| 8 | Encoding | One-hot (`area`, `connection_type`, `has_solar`), ordinal (`house_type`) |
| 9 | Feature scaling | StandardScaler |
| 10 | Feature engineering | Lags, seasonality, ratios, interactions (below) |
| 11 | Feature selection | Mutual information; `payment_mode` dropped |
| 12 | Model training | Naive baseline, Linear Regression |
| 13 | Cross-validation | Expanding-window time-series folds |
| 14 | Hyperparameter tuning | RandomizedSearchCV (Random Forest, Gradient Boosting) |
| 15 | Model comparison | Validation set |
| 16 | Final test evaluation | Untouched test months + permutation importance |
| 17 | Final retraining | Retrained on all labelled data |
| 18 | Serialization | Pipeline + metrics saved with joblib |
| 19 | Deployment | Streamlit app |
| 20 | Monitoring | MAE by month, data drift (PSI), retraining policy |

Steps 7–11 sit inside one **scikit-learn Pipeline**, so everything is learned from training data only and applied identically in the app.

### Engineered features

| Feature | Formula | Why |
|---|---|---|
| `prev_bill` | last month's bill | strongest recent signal |
| `rolling_3m_bill` | mean of last 3 bills | smooths spikes |
| `bill_change` | bill − previous bill | trend up/down |
| `next_month_sin / cos` | cyclic encoding of the month being predicted | seasonality (Dec is next to Jan) |
| `next_is_summer` | next month in Mar–May | AC season jump |
| `units_per_person` | units ÷ family size | usage intensity |
| `ac_x_temp` | ACs × temperature | AC load grows with heat |

### Data quality rules
- **Duplicates:** a record is unique by `customer_id + month`. Repeated rows are removed (latest kept) before features are built, so no month is counted twice.
- **Gaps:** if a customer's previous month is missing, `prev_bill` is left empty and imputed, instead of wrongly using an older bill.
- **No leakage:** lag features only look backwards, the split is by time, and preprocessing is fitted on training data only.

## 6. Results

| Model | Validation MAE (₹) | Validation R² |
|---|---|---|
| Naive baseline (next = current bill) | 442 | 0.79 |
| Linear Regression | 375 | 0.88 |
| Random Forest (tuned) | 265 | 0.93 |
| **Gradient Boosting (tuned)** ✅ | **259** | **0.93** |

**Final test (Jul–Sep 2026):** MAE **₹170** · RMSE ₹297 · R² **0.921** · MAPE 15.0%
(naive baseline on test: MAE ₹220, R² 0.852)

Most important features: current bill, recent bill history, next-month seasonality, and connection type / solar.

## 7. Streamlit app

| Page | What it shows |
|---|---|
| **Existing customer** | Pick a customer to see their bill history chart, next month's predicted bill, an expected range (± test MAE) and a high-bill warning |
| **New customer / what-if** | Enter details (house, ACs, temperature, recent bills) to get a prediction |
| **Batch prediction** | Upload a CSV and download predictions (shows MAE if actual values are present) |
| **Model performance** | Model comparison, CV results, actual vs predicted, feature importance, MAE by month |
